© 2026 AI Timetable Project Presentation

Problem Statement

  • Manual Complexity: Timetable creation is tedious, error-prone, and takes days of effort.
  • Dynamic Conflicts: Handling double-bookings of teachers and rooms simultaneously is a mathematical nightmare.
  • Capacity Constraints: Ensuring room capacity matches student strength per division.
  • Rigidity: Existing tools don't adapt to teacher preferences or historical satisfaction patterns.
  • Scaling Issues: As the number of courses and divisions grows, manual scheduling becomes impossible.
Problem Definition Slide 2

Project Objectives

  • Automation: Generate 100% conflict-free schedules in seconds instead of days.
  • Constraint Satisfaction: Enforce strict "Hard Constraints" while optimizing for flexible "Soft Constraints".
  • Fairness: Implement load balancing to ensure equitable distribution of lectures across faculty.
  • User-Centric UI: Provide a modern, interactive grid for easy visualization and manual fine-tuning.
  • Smart Learning: Utilize Machine Learning to prioritize slots based on historical preference data.
Goals & Vision Slide 3

Project Methodology

Scientific Approach
  • Constraint Modeling: Translation of academic regulations into linear inequalities.
  • State-Space Search: Using CP-SAT to prune impossible branches of the decision tree.
  • Heuristic Optimization: Balancing soft constraints using a weighted objective function.
  • Unit Decomposition: Breaking complex courses into atomic "Solver Units" for granular control.
  • Iterative Solving: Real-time feedback loop allowing users to refine constraints dynamically.
Model: CSP (Constraint Satisfaction Problem)
Solver: Lazy Clause Generation + SAT

Innovation Slide 7

Constraint Logic (CP-SAT)

Mathematical Optimization

Hard Constraints (Non-Negotiable):

  • Teacher Uniqueness: No teacher in two rooms at once.
  • Room Uniqueness: No room holding two different courses at once.
  • Capacity Check: Room size ≥ Division strength.
  • Session Quota: Exactly N sessions per week for each course.

Soft Constraints (Optimized):

  • Minimizing "Gaps" in teacher and student schedules.
  • Prioritizing preferred time slots for specific subjects.
AI Core Slide 8

Machine Learning & Satisfaction

  • Data-Driven: Learns from historical "Constraint Logs" and user satisfaction scores.
  • Feature Extraction: Analyzes `teacher_id`, `course_id`, and `slot_id` to predict high-satisfaction assignments.
  • Dynamic Weights: The solver uses ML predictions to weight soft constraints, making the AI "smarter" over time.
  • Gemini Integration: Uses Generative AI to parse complex natural language requests and explain scheduling logic.
Model: Random Forest / Linear Regressor
Input: Historical Satisfactions -> Output: Optimized Weights for Solver
Intelligence Slide 9

Challenges & Solutions

  • Infeasibility: Solved by implementing a "Constraint Relaxer" that identifies which constraint is preventing a solution.
  • Batch Management: Developed a specific mapping system to link Lab batches to their parent Divisions.
  • Concurrency: Used Redis to manage multiple simultaneous generations without backend crashes.
  • Global Data Consistency: Implemented Alembic migrations to ensure database schema changes are synced across environments.
